# 寵物覺醒系統：劍隱山河討論草案

狀態：2026-10-02，以下保留初始討論草案。使用者已定案並授權實作，現行規格與驗收請以 [覺醒實作文件](pet-awakening-implementation.md) 為準。本草案中的「未定案／未實作」只描述当時狀態。覺醒獨立維護，不納入新卡池 SOP。

## 已取得的方向

使用者提出以高親密度及可能的素材收集作為覺醒條件，利用前版已生成的圖片。使用者已選擇：「保留現行卡圖，覺醒後開放雙形態與演出」。其餘門檻、成本、獎勵與推出範圍都是以下建議，尚未獲得定案。

現行第三版卡圖繼續作為抽卡、圖鑑與陪伴的預設圖。完成覺醒後，開放「初遇／覺醒」形態選擇；初遇相使用重新確認適用的前版圖，覺醒相使用現行第三版圖加上專屬展現。兩相都是同一隻角色，收藏數量與稀有度相同。原先已看得到第三版，所以新增的價值必須包括專屬故事、演出與陪伴回應，不能只靠解鎖一張早已看過的圖。

使用者追問目前正式版是哪個形態：正式版已使用第三版完整展現力量的造型，這套視覺可作為新設計的「覺醒相」；不是換回初始圖。目前沒有覺醒進度或儀式功能，玩家抽到就能看到第三版。未來完成覺醒解鎖的是故事、儀式演出及雙形態切換；不能把現已公開的圖說成必須覺醒後才首次取得。

## 核心提案：感情成熟，完成一次守諾

覺醒代表牠願意把本來獨自承擔的力量，交給你一起完成一件事。山河世界的力量來自守橋、守界、傳授與同行；每隻的試煉需要把這個故事變成可看見的行動。

建議先製作三 UR 的完整原型供討論；首批系統的目標範圍為本池二十隻，每隻一次覺醒。三 UR 的演出更有一方霸主的份量，N／R／SR／SSR 也有自己的故事與成長。不同稀有度不另加重複抽卡門檻；其他卡池是否擴充另行評估。

建議的遊玩順序：

1. 親密度達 Lv.5，完成並領取這隻的 Lv.5 同行故事，看到「牠有一件事，想和你一起完成」。
2. 主動接下專屬守諾約定。候選目標是接下後完成三筆真實任務或習慣事件，以及一次有該角色參與的雲棧古道派遣領取；不要求連續登入，不設失敗倒數。
3. 專屬故事保證給一枚該角色信物。候選儀式配方為「一枚信物＋一份松香行旅糰」。行旅糰已有森林嫩葉6＋豐穗護符2的配方；這是可調整的討論數量，不新增隨機低機率素材或收費。
4. 頁面列出已達成條件、會消耗的物品與獲得內容，由玩家按「與牠共赴此約」。完成覺醒演出，新增紀念篇章與稱號，開放兩相切換。

素材也可採更輕的版本：僅使用試煉保證取得的信物，不消耗行旅糰。要不要額外消耗素材，待討論；不能因為有既有食物就假設所有玩家都備足材料。定案前需估算平均派遣取得量與工坊競爭需求，避免從 Lv.5 陪伴突然變成漫長採集。

## 完成後的體驗

角色頁顯示覺醒紀念標記、一段新增故事、個別稱號，以及「初遇／覺醒」選擇。圖鑑與陪伴頁可記住玩家選擇；抽卡結果繼續使用正式第三版。縮圖需要能辨識選擇的形態，文字仍使用同一角色名稱。

首次完成播放約三至五秒的專屬演出，可略過、重播，減少動態模式使用簡短淡入與靜態重點。重播只播放視覺。雕以巨翼與橋、蛤以界線與淨路、猿以劍與葉分別呈現，不能把同一個金光動畫套給所有角色。

首版建議只增加收藏與陪伴回饋：形態切換、故事、稱號、專屬語句／觸摸回應。派遣數值加成暫不加入，以免覺醒成為取得原有收益的必要步驟。是否增加功能性獎勵，是後續獨立討論項目。

## 舊圖保存與使用資格

已盤點二十組不同的前版／現版圖片，SHA-256 與角色 ID 對應均核對：[資產清單](../reports/awakening-discussion/art-inventory.json)。三 UR 已實際目視比較。封存記錄標為 v2 候選，不能把所有封存圖都稱為第一版；重岳雕另有更早版本保留，尚未選作初遇相。

原本因故事表現不足而被淘汰的圖，可以符合「初遇時尚未展現力量」的語境，但還要逐隻確認物種、身體、風格、名字與故事連續性。既有正式卡图的人工認可不等於前版已獲准作覺醒資產。先保留原路徑與歷史；新用途另外記錄圖像雜湊、形態用途及人工選圖，不改寫原核准文件。

若某張前版有不合適的解剖或角色身份，應先排除或另議修圖，不能只為了不浪費而放進遊戲。目前只是可討論的資產，沒有轉入正式覺醒 catalog、生成新圖或覆蓋任何原圖。

## 與現有進度及存檔的接法（設計約束）

現行親密度門檻為0／50／150／300／500，最高 Lv.5；Lv.5 故事領取後開放日常同行。覺醒狀態另記，不增加假的 Lv.6，不扣親密度、不重置星級，不消耗寵物或要求再抽同一 UR。二十位已有 Lv.2～5 故事與紀念物皆保留。

既有 Lv.5 且已領完故事的角色，可在系統推出後直接接試煉，不必重新送禮或重看四章。試煉建議只計入接下後的新事件；不要求古道100%，也不強制先覺醒其他角色。若採派遣條件，需確認該角色參隊與領取事件，不追溯未保存隊伍的舊紀錄。

新試煉可觀察既有任務／習慣事件，與原同行各自追蹤；不能覆蓋 `bondJourney.active` 或發第二份原同行獎勵。任務撤銷、重複點擊、同一事件多次送達、跨頁操作都要以事件身份去重。親密度升滿後仍應可讀到三筆事件的試煉進度。

未來實作需以永久 `petId` 為鍵，記錄試煉進度、信物領取、覺醒版本、完成時間與偏好形態。素材扣除、一次性獎勵與覺醒完成要在同一交易確認；動畫在交易完成後播放，略過或重新開啟不能重複扣物品與領獎。故事與稱號使用固定身份。

備份新增資料要有格式版本、白名單與遷移：舊備份導入維持未覺醒，已覺醒的新版備份可還原，未知形態安全回到現行預設圖。正式釋出時另驗證離線圖片及演出、同時開兩頁、重複領取、物品不足、操作中斷與備份往返。這些只是設計要求，本次沒有修改 DB、備份格式、App 功能、版本或正式產物。

## 尚待討論

- 條件採「Lv.5＋故事＋守諾試煉」，或再加一份行旅糰；親密度仍是核心。
- 試煉的三筆完成與一次派遣是否合適，能否讓玩家選擇純任務或派遣路線。
- 二十隻一起推出，或先確認三 UR 的完整體驗再分批製作。
- 選定每隻的初遇圖與稱號；首次演出、重播與雙形態頁面需提供實際預覽。
- 首版收藏／陪伴回饋是否足夠；若要派遣加成，另做數值與舊內容平衡提案。

以上均可調整。討論完成前，不將這份文件視為實作批准或正式功能規格。
