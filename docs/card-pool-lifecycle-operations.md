# 卡池生命週期營運與發布

本規則落實 2026-10-10 使用者授權的改善方案。14 天是目標節奏，不是必須犧牲品質趕上的硬期限。

## 每期走同一條路

1. **準備**：維持至少下一期的內容草案；每期原則上一個主要新池。新角色、料理、地區及動畫依既有新池 SOP 驗收，不因生命週期功能省略。
2. **發布前**：確認主線、實際正式 artifact 與公告；更新 `POOL_NAVIGATION.featuredPoolId` 及含時區的 `recommendation.startsAt/endsAt`。首次由本功能啟用起算，後續由新池生效起算，兩者相隔 14 天。發布延後則重新設定並驗證，不能只延後部署卻保留過期倒數。
3. **推薦中**：封面列優先呈現推薦系列；保留星旅之原及全部系列。搜尋只作輔助，所有 active 系列都能點圖選取。
4. **推薦結束**：移除推薦標記，顯示持續開放。保留角色、選池、原池保底與共用相遇碎片；不刪寵物、不清除收藏、不用 active=false 結束一般推薦。
5. **下期**：更新明確推薦 ID 與起訖。歷代系列仍在圖像畫廊，主入口維持固定高度。總池合併、共享保底與特殊限時系列是獨立政策，未經設計及相容性驗證不啟用。

## 日常指定取得

- 每个本地日首次完成非教學任務或有效習慣，合計發放一次 10 枚相遇碎片；不要求連續出席。
- SSR 100、UR 200；同一共用餘額可跨系列與推薦期使用，故事解鎖規則照常。
- 完成紀錄、每日收據及碎片在同一筆 IndexedDB 交易寫入。舊收藏需要轉換時與該筆交易一起處理；失敗全筆回滾。
- 收據使用遞增日期：日期回撥或改到較早時區不會重領，介面說明需等日期恢復。離線可完成，沒有伺服器可信時鐘；本功能不宣稱能阻止修改裝置時間或還原整份舊存檔。
- 新備份保留每日收據；舊備份正常轉換但沒有無從得知的領取歷史。不要把整份還原描述成雲端防作弊帳本。
- 增加了可選的 `encounterEconomy.dailyReceipt`；未發放者沿用舊形狀。回滾程式必須能讀此欄位，否則採前向修正。不可回退玩家錢包或收藏來回滾功能。

## 發布檢查

來源測試：完整 `npm test`、新模組語法、目錄／圖片驗證；隔離瀏覽器涵蓋每日領取、日期邊界、倒數、選池、單抽十連、覺醒預覽、備份、離線，以及三主題和大字級。

視覺驗收：手機與桌面以實際角色、實際長名稱及有效狀態檢查；重點是角色圖像完整、主要按鈕可見、推薦與持續開放清楚、指定邀請不需打字。減少動態效果仍須完整可用。國際設計獎優秀作品的完成度是內部目標，不代表本 App 已獲獎或通過主辦方評選。

先提交來源與 PR，CI 通過後整合；組成固定 preview／production artifact，驗證原生 worker、從上一正式版本正常更新與存檔保留。正式推送只使用已驗證 artifact 的 bytes；Pages 完成後逐檔 HTTPS 雜湊讀回。新發佈不可省略 mailbox 最新 bytes 核對。

## 三週期觀察

在正式首期起點後第 14／28／42 天，整理實際可取得的資料或自願回饋：有效參與日、星塵收入與消耗、抽數分布、穩定／重逢碎片來源、首次指定邀請所需有效日、換池頻率。按新舊玩家分組，避免用重度玩家平均值代表所有人。

目前不新增遙測，也不虛構完成率。10 個有效日對應 100 穩定碎片，是規則可驗證結果；14 個日曆日內是否完成 10 次則是玩家行為，不能直接保證。若取得體驗仍過慢，先檢查進度可見性與資源發放，再評估調整，而不是直接放大星塵或永久退場。
